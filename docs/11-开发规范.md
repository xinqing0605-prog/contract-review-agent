# 11 · 开发规范

## 目录职责

| 目录 | 只放什么 | 禁止 |
| --- | --- | --- |
| `backend/detector.py` | 纯规则检测 | 引入 FastAPI / 数据库 |
| `backend/ingest.py` | 文件 → 文本 | 写数据库 |
| `backend/provider.py` | HTTP 调用模型 | 读写数据库 |
| `backend/model_config.py` | 服务商/模型/模板 | 文档业务 |
| `backend/app.py` | 路由与编排 | 复杂算法 |
| `web/src/components` | 展示 | 直接 `fetch` |
| `web/src/api` | 所有网络请求 | JSX |
| `web/src/hooks` | 状态与副作用 | 渲染 |

原则：**能纯函数就纯函数**。`detector`、`metrics`、`offset` 都是纯的，所以能被测试和评测直接复用。

## Python

- 目标 3.10+，全量类型注解
- 路由内不做复杂逻辑，抽成函数
- 对外错误一律 `HTTPException(status, "中文可读原因")`
- 时间统一用 SQLite `datetime('now')`（UTC），展示层再格式化
- 不打印密钥、令牌、密码

## TypeScript / React

- `strict: true`，不允许 `any`
- 类型导入用 `import type`
- 组件不直接发请求，走 `api` 层
- 派生状态用 `useMemo`，不要每次 render 新建数组当依赖
- 空态 / 错误态 / 加载态三件套必须有

## 命名

| 类型 | 规范 | 例 |
| --- | --- | --- |
| 数据库列 | snake_case | `start_offset` |
| API 字段 | snake_case（与库一致，减少映射） | `key_hint` |
| TS 类型 | PascalCase | `ServiceView` |
| 函数 | 动词开头 | `owned_document` |

## 提交信息

```
<type>(<scope>): <subject>

feat(model): 支持同一服务商下多模型
fix(auth): 修复会话过期后仍可访问
docs: 补充操作手册
refactor(detector): 抽出句子边界函数
test(api): 增加越权访问用例
```

## 数据库变更

1. 先改 `db.py` 的 `SCHEMA`
2. 再写 `_migrate()` 分支：读旧数据 → DROP → 建新表 → 回填
3. 用旧库启动一次，确认数据没丢
4. 补一条迁移测试

## 新增一个条款类型

1. `detector.PATTERNS` 加一条（含正则、基线风险、解释、建议）
2. 需要特殊判断就在 `refine_risk()` 加规则
3. `eval/dataset/cases.jsonl` 加正例 + 负例
4. 跑 `run_eval.py`，确认 F1 没回退
5. 跑 `unittest`

## 新增一个接口

1. `app.py` 或对应模块加路由
2. 必须带 `Depends(current_user)`（除公开接口）
3. 数据访问必须经 `owned_document` / `owned_clause` 校验归属
4. 更新 `docs/06-API接口.md`
5. 补测试（正常 + 未登录 + 越权）

## 代码审查关注点

- 有没有可能跨用户读到数据？
- Key 有没有可能被打日志或返回前端？
- 新增的模型请求地址有没有 SSRF 风险？
- 前端有没有在 render 里发请求？
- 改规则后评测有没有回退？
