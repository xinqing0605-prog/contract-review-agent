# 05 · 数据模型

数据库：SQLite，默认 `backend/clauseguard.sqlite3`，可用 `CLAUSEGUARD_DB` 覆盖。

## 关系总览

```
users 1 ── n documents 1 ── n clauses
  │
  ├── n sessions
  ├── n model_services 1 ── n service_models
  ├── n service_presets
  └── n review_audit
```

## users

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | TEXT PK | `user-<毫秒时间戳>` |
| email | TEXT UNIQUE | 统一转小写 |
| name | TEXT | 昵称，注册可空 |
| password_hash | TEXT | PBKDF2-SHA256 派生值 |
| password_salt | TEXT | 每用户随机 16 字节 hex |
| presets_seeded | INTEGER | 是否已灌过默认模板，防止删光后又自动补回 |
| created_at | TEXT | 默认 `CURRENT_TIMESTAMP` |

## sessions

| 字段 | 说明 |
| --- | --- |
| token_hash | PK，令牌的 SHA-256；数据库泄露也无法直接登录 |
| user_id | 归属用户 |
| expires_at | `datetime('now','+7 days')` |
| last_seen_at | 每次鉴权更新 |

## model_services（服务商 = 分组）

| 字段 | 说明 |
| --- | --- |
| id | `svc-<随机>` |
| user_id | 归属 |
| name | 显示名，同用户内唯一（应用层校验） |
| kind | 大模型 / 综合服务 / 本地模型 / 自定义 |
| created_at / updated_at | — |

## service_models（模型 = 真正的连接）

| 字段 | 说明 |
| --- | --- |
| id | `mdl-<随机>` |
| service_id | 所属服务商 |
| user_id | 冗余一份，便于直接按用户查询 |
| name | 模型标识，如 `qwen-plus`；同服务商内唯一 |
| description | 说明 |
| base_url | 接口地址（如 `https://api.deepseek.com`） |
| api_key_enc | Fernet 加密后的 Key |
| key_hint | 掩码，如 `sk-a…3456` |
| is_active | 是否「当前使用」，全用户最多一条 |
| verified_at | 最近一次测试连接成功时间 |
| UNIQUE(service_id, name) | 同服务商下模型不重名 |

## service_presets

服务商模板，只存名称 + 地址，用于新建服务商时快速填充。

| 字段 | 说明 |
| --- | --- |
| id | `preset-<随机或 user-id-序号>` |
| label | 模板名，如「阿里通义 / Qwen」 |
| base_url | 地址 |

## documents

| 字段 | 说明 |
| --- | --- |
| id | `doc-<毫秒时间戳>`（同毫秒可能冲突，见已知问题） |
| user_id | 归属 |
| name / owner | 名称 / 负责部门 |
| text | 解析后的纯文本（原文，不是切片） |
| status | `pending` / `reviewed` |
| source_type | `text` / `txt` / `md` / `docx` / `pdf` |
| file_path | 原始文件相对路径，如 `uploads/user-1/doc-2.docx` |
| deleted | 软删除标记，列表与访问都过滤 |
| created_at | — |

## clauses

| 字段 | 说明 |
| --- | --- |
| id | `<doc_id>-<序号>` |
| document_id | 所属合同 |
| title | 条款类型（8 类之一） |
| risk | `high` / `medium` / `low` |
| excerpt | 列表用摘要（超 120 字截断） |
| original | 正文精确切片，**必须** `text[start:end] == original` |
| reason / recommend | 风险解释 / 修改建议 |
| start_offset / end_offset | 字符下标，左闭右开 |
| accepted | 0 未处置 / 1 已采纳 |
| comment | 批注 |
| updated_at | 最近处置时间 |

## review_audit

| 字段 | 说明 |
| --- | --- |
| id | 自增 |
| document_id / user_id | 归属 |
| action | `upload` / `review` / `approve_clause` / `reject_clause` / `comment_clause` / `delete` |
| payload | JSON 字符串，各动作自定义 |
| created_at | — |

## 迁移策略

`db.init()` 在应用启动时执行，顺序：

1. `executescript(SCHEMA)` —— 只建不存在的表
2. `_migrate()` —— 对已有库补列 / 补表 / 形状转换
3. `seed()` —— 首次创建演示账号与样例合同

已实现的迁移：

| 版本 | 变更 | 处理方式 |
| --- | --- | --- |
| v1 → v2 | documents 增加 user_id / source_type / deleted | `ALTER TABLE ADD COLUMN` + 归属演示账号 |
| v5 → v6 | 单套模型配置 → 多服务商 | 建新表、迁数据、删旧表 |
| v7 → v8 | 服务商带地址 Key → 模型带地址 Key | 重建两张表，地址/Key 下沉到每个模型 |

原则：**先读旧数据到内存，再 DROP，再建新表，再回填**。不做原地改列，避免 SQLite 的 ALTER 限制。

## 备份

```powershell
Copy-Item backend\clauseguard.sqlite3 backup\clauseguard-$(Get-Date -Format yyyyMMdd-HHmm).sqlite3
Copy-Item data backup\data-$(Get-Date -Format yyyyMMdd-HHmm) -Recurse
```

注意：`data/.master.key` 必须一起备份，否则模型 Key 无法解密。
