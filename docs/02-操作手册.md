# 02 · 操作手册（全流程走查）

> 用途：按顺序走一遍，把每个功能都点一次。每步有**操作 / 预期 / 不符合时怎么查**。
> 建议边做边在最后的《验收清单》打勾。

前置：已完成 [01-快速开始](01-快速开始.md)，服务已在 http://127.0.0.1:8103 运行。

## 第 1 步 · 登录与注册

**操作**

1. 打开 http://127.0.0.1:8103
2. 用演示账号登录：`demo@clauseguard.local` / `demo1234`

**预期**

- 进入主界面，顶栏出现 `demo@clauseguard.local`
- 左侧「文档」显示 3 份示例合同
- 顶栏「已连接」右侧显示当前模型标签（未配置时显示「未配置模型」）

**再试一次注册**

1. 点「退出」回到登录页
2. 切到「注册」，用**邮箱或用户名** + 两次一致的密码（至少 8 位）注册

**预期**：注册成功直接进入，左侧文档为 **0 份**（新账号数据隔离）

**不符合时**

| 现象 | 原因 |
| --- | --- |
| 提示"邮箱或密码不正确" | 大小写 / 全角字符；邮箱会被转小写 |
| 注册报"这个邮箱已经注册过了" | 换一个邮箱 |
| 提示"失败次数过多" | 同邮箱 10 分钟内失败 8 次会锁定 |

- [ ] 通过

## 第 2 步 · 配置模型（服务商 → 模型）

> 这一步最容易出错，请严格按顺序点。

**2.1 新建服务商**

1. 点右上「模型设置」
2. 点左侧底部「+ 添加服务商」
3. 弹窗填：名称 `Qwen`、类型 `大模型`
4. 点「添加服务商」

**预期**：左侧列表出现 `Qwen`，显示 `0 个模型 · 大模型`，右侧提示"还没有模型"

**2.2 添加模型**

1. 右侧点「+ 添加模型」
2. 弹窗填：
   - 模型标识：`qwen-plus`
   - 完整接口地址：`https://dashscope.aliyuncs.com/compatible-mode/v1`
     （可直接点下方「阿里通义」快捷按钮填入）
   - API Key：你的真实 Key
   - 说明：通义千问
3. 点「添加模型」

**预期**：右侧出现模型卡片，显示地址、`已配置 sk-…xxxx`、`当前使用` 标签

**2.3 再添加一个模型**

重复 2.2，模型标识改成 `qwen-max`，地址和 Key 同样填写。

**预期**

- 同一服务商下出现两张卡片
- 第一个模型带「当前使用」，第二个没有
- 弹窗高度**不变**，右侧区域内部滚动

**2.4 测试连接**

点第二个模型卡片上的「测试连接」。

**预期**：顶部出现绿色提示 `连接成功：qwen-max（1234 ms）`，卡片右上显示 `已验证 <时间>`

**2.5 切换当前模型**

点第二个卡片的「设为当前」。

**预期**：`当前使用` 标记移到第二个模型；关闭弹窗后，**顶栏模型标签应立即变成 `Qwen · qwen-max`**

**2.6 重名校验**

- 再点「+ 添加服务商」，名称仍填 `Qwen` → **预期 409**「已经有同名服务商「Qwen」」
- 在 Qwen 下再添加模型，标识仍填 `qwen-plus` → **预期 409**「这个服务商下已经有模型「qwen-plus」」

**不符合时**

| 现象 | 原因 |
| --- | --- |
| 提示"域名解析失败" | 地址写错或断网 |
| 提示"公网地址必须使用 https" | 用了 http |
| 提示"服务端已禁止访问内网地址" | 填了 127.0.0.1 等内网地址 |
| 提示"Key 无效或已失效" | Key 错误或与地址不匹配 |
| 测试成功但审阅没走模型 | 该模型没被「设为当前」 |

- [ ] 通过

## 第 3 步 · 导入合同（两种方式）

**3.1 上传文件**

1. 左侧点「上传文件」，选一个 `.docx` 或 `.pdf` 合同
2. 观察左侧列表

**预期**

- 新合同出现在列表顶部，标记 `待审阅 · 0 条`
- 中间显示合同原文，字数与文件一致

**3.2 粘贴文本**

1. 点「粘贴」→ 输入名称和正文（≥20 字）→ 导入

**预期**：同上

**不符合时**

| 现象 | 原因 |
| --- | --- |
| 拒绝 .docx | 后端没装 python-docx |
| "解析后只有 N 个字符" | 扫描版 PDF 没有文字层，需要 OCR |
| 413 | 解析后超过 30 万字符 |

- [ ] 通过

## 第 4 步 · 运行审阅（观察流式链路）

**操作**

1. 选中一份合同
2. 点右上「运行审阅」

**预期**

右侧「审阅链路」**逐步出现**（不是一次性刷出来）：

```
1 读取文档      131 字符 · 来源 docx
2 条款切分      识别 4 条候选条款
3 模型审阅      qwen-max · 1234 tokens · 2100 ms     ← 已配置模型时
4 风险分级      高 2 / 中 2 / 低 0
5 生成建议      已写入，等待人工确认
```

顶部「单份耗时」由 `—` 变成具体秒数。

**如果没配模型**：第 3 步显示 `模型审阅 跳过 · 未配置模型，使用规则解释`，其余步骤照常——这是**降级路径**，功能不中断。

**不符合时**

| 现象 | 原因 |
| --- | --- |
| 链路一次性出现 | 浏览器不支持流式，走了回退接口（功能不受影响） |
| 第 3 步失败后仍继续 | 预期行为：模型失败自动降级为规则解释，界面会标红提示 |
| 报 404 | 该合同属于别的账号 |

- [ ] 通过

## 第 5 步 · 原文高亮与双向联动

**操作**

1. 观察中间原文：条款被高亮（红=高、黄=中、青=低）
2. 点原文里的红色高亮
3. 点中间「识别条款」里的某张卡片

**预期**

- 点原文高亮 → 右侧条款详情切换，条款列表对应卡片高亮
- 点条款卡片 → 原文自动滚动到该句并加粗边框
- 风险筛选（全部/高/中/低）数字与卡片数量一致

**不符合时**：如果高亮位置错位，说明 `start_offset/end_offset` 与正文不一致——用第 8 步的接口自检。

- [ ] 通过

---

## 第 6 步 · 处置与批注

**操作**

1. 选中「付款与验收」
2. 在「批注」框输入：`已与供应商确认改为 60 日`
3. 点「保存批注」
4. 点「采纳建议」

**预期**

- 批注保存后灰色提示「未保存」消失
- 卡片出现 `已确认` 标记，顶部「已确认」计数 +1
- 详情底部按钮变为「已采纳 / 撤销」

**再点一次「撤销」** → 预期恢复未采纳状态。

- [ ] 通过

---

## 第 7 步 · 审计日志

**操作**

点顶栏「审计」。

**预期**：时间倒序展示，至少包含

```
导入合同     131 字符 · docx
执行审阅     4 条条款 · 2 条高风险 · deepseek
保存批注     ...
采纳建议     付款与验收
```

**不符合时**：审计按文档隔离，切到别的合同看到的是另一份记录。

- [ ] 通过

---

## 第 8 步 · 导出报告

**操作**

1. 点顶栏「导出报告」→ 选 `Word (.docx)`
2. 再选 `Markdown (.md)`

**预期**

- 浏览器直接下载 `.docx`，用 Word 打开包含：合同名、负责部门、审阅结论、每条条款（风险等级/原文/解释/建议/处置/批注）
- `.md` 用编辑器打开结构正常

**不符合时**：按钮置灰说明当前合同没有条款，先运行审阅。

- [ ] 通过

---

## 第 9 步 · 重新审阅（验证人工结果不被冲掉）

**操作**

1. 回到第 6 步那份已采纳、已批注的合同
2. 再点一次「运行审阅」

**预期**

- 条款重新生成，但**已采纳状态和批注仍在**（按条款类型匹配保留）
- 审计日志新增一条「执行审阅」

- [ ] 通过

## 第 10 步 · 数据隔离验证

**操作**

1. 记下当前合同的 ID —— 在中间「合同原文」面板标题下方可以看到，形如 `ID doc-1792...`
2. 退出 → 登录到第 1 步注册的新账号
3. 尝试访问原合同的接口：

```powershell
Invoke-RestMethod http://127.0.0.1:8103/api/documents/<原合同ID>/text
```

**预期**：返回 **404**（不是 403 —— 不暴露"这个 id 存在"）

新账号的文档列表也应为空。

- [ ] 通过

## 第 11 步 · 持久化（重启不丢）

**操作**

```powershell
.\start_all.ps1 -Stop
.\start_all.ps1
```

然后用原账号登录。

**预期**

- 合同、条款、批注、审计记录都还在
- 模型配置（服务商/模型/Key 掩码）还在
- **不需要重新登录**（会话存在数据库里，7 天有效）

- [ ] 通过

---

## 第 12 步 · 删除与回收语义

**操作**

1. 鼠标悬停左侧合同 → 点右侧 `×` → 确认删除
2. 观察列表

**预期**

- 合同从列表消失
- 用接口再查该合同 → 404
- **审计记录仍保留在数据库**（软删除，符合合同系统合规预期）

- [ ] 通过
