# 12 · 变更记录

## v18 · 模型调用可观测

- 新增 `llm_calls` 表：记录每次模型调用的模型名、prompt / completion / total token、耗时、成功或失败原因
- 新增 `backend/llm_stats.py`：写记录 + 按天 / 按模型聚合，P95 用最近秩法
- 审阅流程（成功与失败）与模型连通性检测都会落库；记录是**旁路逻辑**，写失败只打警告，不影响审阅
- 新增接口 `GET /api/metrics/llm?days=7`，按账号隔离
- 顶栏新增「用量」入口：近 7 / 14 / 30 天的调用次数、token 合计、平均与 P95 耗时、失败次数，按模型分组，并可查看最近调用
- 新增 `tests/test_llm_stats.py`（5 项）：成功/失败计数、用户隔离、异常 usage 容错、接口鉴权与归属过滤

## v17 · 模型审阅提速与时间显示修正

- 模型审阅只处理**高/中风险条款**，低风险直接用规则解释，减少无用调用
- 提示词要求每条理由与建议**不超过 40 字**，`max_tokens` 从 2200 降到 1200
- 修复模型卡片“已验证”时间显示为 UTC 的问题，改为按本地时区显示
- 效果：2877 字符文档的模型审阅从 65 秒降到约 30 秒（7 条条款时）

## v16 · 审批门禁与幂等执行

从客服工单项目中移植的两个机制：

- **服务端强制审批状态机**：`pending → approved / rejected → executed`
  - 未审批的条款不能执行（409）
  - 已执行的条款不能再驳回或改回审批状态
  - 驳回必须填写理由，所有状态变更写入审计
- **幂等执行**：重复调用执行接口返回同一结果（`replayed: true`），不会产生重复审计
  支持 `Idempotency-Key` 请求头做接口级重放
- 重新审阅会保留条款的审批状态与驳回理由
- 已驳回的条款可以修改驳回理由（同一理由重复提交视为重放）
- 驳回弹框改为项目内模态框，不再使用浏览器原生 prompt
- 新增通用确认框组件：删除合同、删除服务商、删除模型统一使用项目内弹窗，前端不再出现任何浏览器原生 confirm / alert / prompt

## v10 · 走查问题修复

- **风险分级不再被模型覆盖**：模型只写解释与建议，风险等级由规则决定，保证同一合同每次结果一致
- **修复审阅链路闪一下消失**：前端误用后端不存在的 `trace` 字段把步骤清空了
- **审计记录真实模型名**：原来写死 `deepseek`，现在记录实际使用的模型
- **审计时间按本地时区显示**：数据库存 UTC，界面转本地
- 新建模型时 API Key 改为必填并校验长度
- 顶栏「已连接」改为「服务在线」，避免误解为模型已连通
- 合同原文面板显示合同 ID
