# 08 · 测试与评测

## 三层验证

| 层 | 位置 | 跑法 | 覆盖 |
| --- | --- | --- | --- |
| 单元测试 | `tests/test_workflow.py` | unittest | 规则检测、句子边界、文件解析 |
| 接口与租户测试 | `tests/test_api.py` | unittest（临时库） | 登录、隔离、越权 404、密钥不回显、级联删除 |
| 用量统计测试 | `tests/test_llm_stats.py` | unittest（临时库） | 调用记录、按模型聚合、用户隔离、异常 usage 容错、接口鉴权 |
| 语义召回测试 | `tests/test_semantic.py` | unittest（注入假向量） | 同义句召回、无关句不召回、阈值钳制、规则覆盖去重、设置接口 |
| 真实 HTTP 冒烟 | `tests/smoke.py` | 需先起服务 | Cookie 会话、SSE、导出、登出 |
| 条款评测 | `eval/run_eval.py` | 独立脚本 | 检出准确率、风险分级、引用接地 |

## 跑测试

```powershell
cd F:\contract-review-agent

# 全部单元 + 接口测试
.\.venv\Scripts\python.exe -m unittest discover -s tests -t .

# 真实 HTTP 冒烟（先启动服务）
.\start_all.ps1
.\.venv\Scripts\python.exe tests\smoke.py
```

> 接口测试会在系统临时目录建独立数据库，不会碰开发库。

## 跑评测

```powershell
.\.venv\Scripts\python.exe eval\run_eval.py
```

输出终端表格 + `eval/reports/report.json` + `eval/reports/report.md`。

指标口径：

| 指标 | 定义 |
| --- | --- |
| Precision / Recall / F1 | 条款**类型**层一对一匹配，同类型才允许配对 |
| 定位 IoU | 命中片段与标注片段的交并比，默认阈值 0.5 |
| 风险分级准确率 | 匹配上的条款里风险级别一致的比例 |
| 原文引用接地率 | `text.slice(start,end) === original` 的比例，必须 100% |

当前基线：

| 版本 | P | R | F1 | 说明 |
| --- | --- | --- | --- | --- |
| v1 | 0.800 | 0.857 | 0.828 | 取全文第一个命中、`数据` 无约束、无负向规则 |
| v2 | 1.000 | 0.929 | 0.963 | 改选最具体分句、收紧正则、加 `不可抗力` 排除 |

唯一漏检是同义改写用例（"单方解除且无需补偿"，无关键词），即规则天花板，也是下一步接语义召回的理由。

**注意**：8 例只是冒烟集，数字不代表真实世界表现。扩到 50 例并留 holdout 才具说服力。

## 怎么加评测用例

编辑 `eval/dataset/cases.jsonl`，一行一个 JSON：

```json
{"id":"case-09","name":"劳动合同","text":"……","gold":[
  {"type":"责任限制","risk":"high","quote":"甲方有权单方解除且无需支付补偿。"}
]}
```

规则：

1. **以句子为单位**，检测器输出就是句子
2. 写 `quote` 不写偏移量，脚本用 `resolve_quote` 反查，找不到或不唯一会直接报错
3. `quote` 必须在正文中唯一
4. 必须有负样本（`gold: []`），专测误报

## 前端检查

```powershell
cd web
npx tsc --noEmit      # 类型

```

## 改代码后的最小检查清单

1. 改了规则 → 跑 `unittest` + `run_eval.py`，看 F1 是否回退
2. 改了接口 → 跑 `unittest` + `smoke.py`
3. 改了前端 → `tsc --noEmit` + `build` + 手动点一遍相关流程
4. 改了数据库 → 用旧库启动一次，确认迁移不丢数据
