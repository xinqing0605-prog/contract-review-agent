# 条款检测评测

跑一次就知道现在的检测到底行不行，以及改动之后是变好还是变坏。

```powershell
cd F:\contract-review-agent
python eval\run_eval.py
```

输出：终端表格 + `eval/reports/report.json` + `eval/reports/report.md`（可直接贴进 README）。

## 为什么要有这一层

没有评测的 AI 项目只能证明"跑通了"，不能证明"好用"。面试官问
「你怎么知道它变好了」，答不上来就说明项目停在 demo 阶段。

## 指标口径

| 指标 | 定义 |
| --- | --- |
| Precision / Recall / F1 | 条款**类型**层面的一对一匹配，同类型才允许配对 |
| 定位 IoU | 命中片段与标注片段的交并比，默认阈值 0.5 |
| 风险分级准确率 | 在匹配上的条款里，风险级别一致的比例 |
| 原文引用接地率 | `text.slice(start, end) === original` 的比例，必须是 100% |

接地率是硬约束：报告的「原文片段」必须是正文的精确切片。这一项只要不是 100%，
说明有环节在生成原文，属于安全事故，不是精度问题。

## 标注规范

`eval/dataset/cases.jsonl`，一行一个用例：

```json
{"id":"case-01","name":"供应商服务合同","text":"……","gold":[
  {"type":"付款与验收","risk":"high","quote":"甲方在收到乙方发票并验收合格后九十日内支付全部款项，逾期付款不承担利息或其他责任。"}
]}
```

规则：

1. **以句子为最小单位**。检测器输出就是句子，标注也用句子，IoU 才有意义。
2. **写 `quote` 不写偏移量**。脚本用 `resolve_quote` 反查位置，找不到或不唯一会直接报错，
   这是防止手数错位置。
3. **`quote` 必须在正文里唯一**。重复的话加长到能唯一定位。
4. **必须有负样本**。`gold: []` 的用例专门测误报，这类用例比正样本更能暴露关键词匹配的问题。
5. **风险按业务判断写**，不要照抄检测器的输出，否则等于自己给自己打分。

## 扩到 50 例

8 例只是冒烟集，用来保证管线能跑。真正的作品集需要 50 例以上：

- 来源：脱敏的真实合同（最好）、公开合同模板、自己改写
- 覆盖：不同合同类型（采购 / 服务 / 渠道 / 劳动），长短各半
- 负样本占比 20% 左右
- 至少留 10 例当 holdout，调规则时不许看

## 已知问题（用评测跑出来的）

| 现象 | 原因 | 下一步 |
| --- | --- | --- |
| 同义改写检测不到（"单方解除且无需补偿"） | 纯关键词，没有语义 | 加 LLM 召回：规则先出候选，模型判定，再合并 |
| 一个类型只取一处 | 每类只保留最具体的一句 | 同类多处命中时应全部返回 |
| 条款边界依赖中文标点 | 无标点的长句会被 320 字截断 | 加段落级兜底 |
